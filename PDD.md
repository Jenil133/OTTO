# OTTO × PDD — Show Me Your Prompt Driven Development

> **Otto is PDD twice over.** The product runs on prompts — a spoken ask becomes a planner
> prompt, which composes per-site agent prompts, which feed a synthesizer prompt. And the
> build ran on prompts — the phase files in `docs/prompts/` were fed verbatim to coding
> agents that generated every screen, adapter, and test in this repo.

---

## 1 · The product is prompt-driven

```
 spoken / typed ask
        │
        ▼
 backend/prompts/planner.md ──strict JSON──▶ Plan (pydantic-gated, backend/schemas.py)
        │
        │  the planner COMPOSES a natural-language `instruction` per subtask
        ▼
 per-site agent instructions ──▶ read-only web agents (Retriever) ──▶ AgentResults
        │
        ▼
 backend/prompts/synthesizer.md ──▶ spoken answer + results card (docs/CONTRACTS.md §1)
```

**Rule: prompts are the interfaces between every component; the code between them is
dispatch plumbing** (`backend/pipeline.py` is ~an event loop that moves JSON between prompts).
The planner writes the agents' briefs at runtime — **prompts generating prompts**: each
subtask carries `instruction`, `success_criteria`, and `output_schema` authored by the
planner prompt itself (see the field rules in `backend/prompts/planner.md`).

| Runtime prompt | File | Stage |
|---|---|---|
| Planner (rules, allowlist injection, JSON schema, honesty path) | `backend/prompts/planner.md` | plan |
| Per-site agent instructions | composed at runtime by the planner | act |
| Synthesizer (merge rules, honesty paths, screenshot recovery) | `backend/prompts/synthesizer.md` | answer |
| Otto voice personality (ElevenLabs, Phase 3) | `backend/prompts/personality.md` | speak |
| Watch-condition compare (Phase 4) | `backend/prompts/watch-compare.md` | watch |

Safety lives **in the prompt and in code**: read-only Zone-1 rules are written into
`backend/prompts/planner.md`, and a pydantic validator (`on_allowlist`, `backend/schemas.py`)
rejects any target not on `docs/ALLOWLIST.md` — belt and suspenders.

## 2 · The build is prompt-driven — literally

The files in `docs/prompts/` are not documentation *about* the build. They **are** the
build: each was pasted verbatim into coding agents (Claude Code multi-agent workflows),
which generated the code. **Prompt files are source; code is generated output.**

| Prompt artifact (source) | Generated output | Verified by |
|---|---|---|
| `docs/prompts/phase-1.md` | all of `frontend/` (5 screens, mock engine, design system) | browser run at `?mock=1`, zero console errors; `npx vite build` passes |
| `docs/prompts/phase-2.md` | `backend/pipeline.py`, `backend/adapters/`, `backend/tests/`, runtime prompts | 29/29 pytest at phase-2 close (suite has grown since — run it for the live count); live end-to-end run in 16s |
| `docs/prompts/architecture-diagrams.md` | one-stream event design (D4), safety zones (D5), crash-net (D7) | contract tests in `backend/tests/test_pipeline.py` |
| `docs/prompts/README-master-plan.md` | phase gates, cut order, contract freeze discipline | `completed/phase-1-status.md`, `completed/phase-2-status.md` |

Honest kicker: **this very file was generated by a coding agent from that same prompt
pack.** The PDD evidence document is itself PDD output.

## 3 · The six-stage PDD cycle, mapped to Otto

| Stage | How Otto did it | Artifact |
|---|---|---|
| **Define** | Phase files with acceptance criteria + contracts frozen before parallel work | `docs/prompts/phase-*.md`, `docs/CONTRACTS.md` ("FROZEN" header) |
| **Constrain** | ≤3 subtasks + allowlist-only targets enforced by pydantic; read-only rules authored inside the planner prompt | `backend/schemas.py` (`on_allowlist` validator), `backend/prompts/planner.md` |
| **Generate** | Multi-agent coding run off the prompt pack — frontend, backend, tests | the entire repo |
| **Verify** | 7-level validation ladder, static → live demo | `docs/VERIFY-LADDER.md`, `docs/VERIFY.md` |
| **Review** | Adversarial review blockers fixed (WS broadcast snapshot, allowlist gate, reducer crash) + 4 live-only bugs found and fixed | `completed/phase-2-status.md` §"Four bugs" |
| **Back-propagate** | Live-run lessons written back into the checklist and adapters: temperature gotcha, `<think>` stripping, 75s timeout | `docs/VERIFY.md` §"Gotchas found live"; `backend/adapters/kimi.py`, `backend/adapters/minimax.py` |

### The strongest artifact: planner model chosen by measurement, not vibes

Same gateway (TokenRouter), same key, same prompt — measured live (`docs/VERIFY.md`):

| Model | Latency | Plan quality |
|---|---|---|
| **google/gemini-3.5-flash-lite** | **2.8s** | 3 subtasks — **shipping** (5/5 consistency runs, 2.6–2.9s) |
| openai/gpt-5.4-mini | 3.9s | 1 subtask — rejected, breaks the fan-out |
| x-ai/grok-4.1-fast | 7.6s | 3 subtasks |
| z-ai/glm-5-turbo | 10.4s | 3 subtasks |
| moonshotai/kimi-k3 | 28.0s | 3 subtasks (reasoning model — wrong tool for a 5–10s budget) |

Swap = one env var (`PLANNER_MODEL`), zero code change. The prompt is the interface;
the model behind it is a config value.

## 5 · Definition of Done — scored honestly

| # | Criterion (PDD guide) | Status |
|---|---|---|
| 1 | Observable acceptance criteria satisfied | ✅ CP1 script passed live; phase acceptance in `completed/*-status.md` |
| 2 | Positive **and** negative paths tested | ✅ clarification / off-allowlist / all-failed / crash-net — see §4 |
| 3 | Issue, code, tests, docs agree | ✅ `docs/CONTRACTS.md` is the single source; tests assert its shapes |
| 4 | No secrets in diff or logs | ✅ key lives only in `backend/.env` (gitignored); `.env.example` has names only |
| 5 | Tests + CI pass | ⚠️ full suite passes locally (36 at this writing); **CI pending Saturday** — no GitHub repo until morning push |
| 6 | Exact demo flow works manually | ✅ live run + `?mock=1` golden replay both exercised in the browser |
| 7 | Linked PR passes checkup | ⚠️ **pending Saturday** — PR lanes start at first push |

Two honest ⚠️s, both for the same reason: the repo goes to GitHub Saturday morning.
Everything a repo-less project *can* have green is green — and nothing was weakened to
get there (`--protect-tests` spirit: the 4 live bugs were fixed in adapters, never in tests).
